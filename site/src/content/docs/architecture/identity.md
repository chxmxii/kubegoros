Keycloak runs in the `keycloak` namespace, managed by the Keycloak Operator, with its database on a two-instance CloudNativePG cluster. All logins go through one realm, `kubegoros`, at `https://keycloak.lab.chxmxii.xyz/realms/kubegoros`.

## Groups and permissions

Access is controlled by membership in two Keycloak groups.

| Group | ArgoCD | Grafana | Kubernetes API, Headlamp | Prometheus, Alertmanager, Longhorn, Hubble |
|---|---|---|---|---|
| `k8s-admins` | `role:admin` | Admin | `cluster-admin` | allowed |
| `k8s-viewers` | `role:readonly` | Viewer | `view` | refused |
| neither | no access | refused | no permissions | refused |

Tokens carry the groups in a `groups` claim. The Kubernetes API server prefixes them with `oidc:`, so the RBAC subjects are `oidc:k8s-admins` and `oidc:k8s-viewers` (see `kubernetes/apps/security/cluster-rbac`).

## How each app authenticates

**Native OIDC.** ArgoCD, Grafana and Headlamp each have their own Keycloak client and read the `groups` claim directly.

**Gateway SSO.** Prometheus, Alertmanager, Longhorn and Hubble have no login of their own. An Envoy Gateway `SecurityPolicy` on each route runs the OIDC flow with the `edge-proxy` client, verifies the resulting ID token against Keycloak's keys, and only forwards requests whose token has `k8s-admins` in `groups`. Everyone else gets a 403. Logging out is `/oauth2/logout` on the app's hostname.

**Kubernetes API.** kube-apiserver is started with a structured `AuthenticationConfiguration` that accepts Keycloak ID tokens with audience `kubernetes` (kubectl) or `headlamp`. Usernames come from `preferred_username`, prefixed `oidc:`. Headlamp sends the signed-in user's token to the API, so Headlamp actions are limited by that user's RBAC.

## Clients

| Client | Type | Used by |
|---|---|---|
| `argocd` | confidential | ArgoCD UI |
| `argocd-cli` | public, PKCE | `argocd login --sso` |
| `grafana` | confidential | Grafana |
| `headlamp` | confidential | Headlamp |
| `edge-proxy` | confidential | Gateway SSO for apps without their own login |
| `kubernetes` | public, PKCE | `kubectl` through kubelogin |

Confidential client secrets are generated by `hack/vault-seed.sh`, stored in Vault at `secret/keycloak-clients`, and delivered by External Secrets to both Keycloak and each app.

## Realm policy

- New users must enroll a TOTP authenticator at first login.
- Passwords need 14 characters, cannot contain the username or email, and cannot repeat the last 5.
- Five failed logins lock the account, starting at one minute and growing to 15 minutes.
- Self-registration is off. Access tokens live 5 minutes, idle sessions end after 30 minutes.

:::caution
The operator imports the realm only when it does not exist. Editing `realm.yaml` later does not change a running Keycloak. Make the change in the admin console as well, or delete the realm and let it be imported again.
:::

## Using kubectl

Install [kubelogin](https://github.com/int128/kubelogin) and add a user to your kubeconfig:

```bash
kubectl config set-credentials keycloak \
  --exec-api-version=client.authentication.k8s.io/v1 \
  --exec-command=kubectl \
  --exec-arg=oidc-login \
  --exec-arg=get-token \
  --exec-arg=--oidc-issuer-url=https://keycloak.lab.chxmxii.xyz/realms/kubegoros \
  --exec-arg=--oidc-client-id=kubernetes \
  --exec-arg=--oidc-extra-scope=groups \
  --exec-arg=--oidc-extra-scope=email
kubectl config set-context lab --cluster=kubegoros --user=keycloak
kubectl --context lab auth whoami
```

`auth whoami` should print `oidc:<your username>` with `oidc:k8s-admins` in its groups.
